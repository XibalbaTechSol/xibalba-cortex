# Handoff: the Cortex console theme and mockups

For the agent (or person) who picks this up. It says what was decided, what is already built, what is
only designed, and exactly how to continue. Read it top to bottom once; the tables are for lookup.

- **Code:** `viewer/src/console/` (React 19, Vite 8, TypeScript, `three`, `react-force-graph-2d`). Branch
  `claude/cortex-ui-redesign-grvfi8`, draft PR [#46](https://github.com/XibalbaTechSol/xibalba-cortex/pull/46).
- **Mockups:** the Claude Design canvas, <https://claude.ai/artifact/ABHJes1bpQ2BLDkBWx1cj3> (128 boards).
  `DESIGN.md` is the generated map from every board to the files that produce it.
- **Theme source:** the *Xibalba Console* design system, <https://claude.ai/artifact/K8E9C4RJtQLLzkNgv3ENB7>
  (it follows the "Industry" mock, not Shield's drifted CSS). Its tokens are copied into
  `src/console/tokens.css`.
- **What is exposed vs not:** `COVERAGE.md` (generated by `scripts/ui_coverage.py`; a test fails if a new
  MCP tool or route is not classified).

## 1. The one-paragraph version

The console is **two lenses and a set of tools**. **Graph** (3D by default, 2D optional) and **Timeline**
are the only destinations. Everything else (Memories, Entities, Sessions, Operations, Agents, Settings,
Recall, Review, Integrity) is a **drawer or dialog that opens over the lens it was opened from**; the lens
stays mounted underneath. Dark only. Square, flat, graphite, with registration crosses on every window and
one lavender accent. Nothing is shown as checked that was not checked.

**State of the work.** The console is **complete against the backend**: it is the only UI (the old viewer is deleted), and every HTTP route and MCP tool is either a console surface or deliberately not one, with the reason, in `COVERAGE.md` (a test fails if a new one is unclassified). It is verified by `tsc`, `oxlint`, 281 unit tests, the full Python suite, and **95 headless Playwright tests** against the real API (`npm run test:e2e`, run in CI as job `viewer`). The 17 capabilities that were once only designed ("Planned" boards) are built; section 8 lists where each lives. What remains is listed in section 9.

## 2. Run it

```bash
# API: a fixture profile with realistic backdated data (scratch only; the script refuses a real profile)
python scripts/dev_seed_console.py --home /tmp/cortex-dev
python -m xibalba_cortex.local_api --home /tmp/cortex-dev        # :8420

# viewer
cd viewer && npm install
CORTEX_HOME=/tmp/cortex-dev npm run dev                          # :5190, proxies /cortex-api with a dev operator token

npx tsc -b && npx oxlint src && npx vitest run                   # the gates
```

- The dev proxy issues an **operator bearer token**, so the console runs as a *token*, not an *account*.
  Settings → Account therefore shows "a token has no account"; the signed-in account design was captured
  with stubbed responses (section 9).
- The previous viewer is gone (`App.tsx`, `index.css`, `?ui=legacy`, the landing page, Mermaid and the dependencies only it used). The console is the only UI.
- If search or any route returns a surprising 404, **restart the API**; a stale process is the usual cause.

## 3. The theme

Everything is in `tokens.css`; use the variables, never the hex.

| Token | Value | Use |
|---|---|---|
| `--ground` / `--panel` | `#0d0f11` | the page, every window and the top bar: one graphite. This is the dark background Shield's command-center theme uses (`--bg` and `--panel` alike in `xibalba-shield/ui/src/App.css`); it replaced the mock's `#14171a` by the owner's choice |
| `--elevated` | `#262b30` | only on inputs and genuinely raised states (same value in Shield) |
| `--hairline` / `--hairline-strong` | `rgba(255,255,255,.14)` / `.35` | controls (buttons, inputs, tabs) |
| `--frame-line` / `--frame-tick` | `rgba(92,100,106,.28)` / `rgba(171,181,188,.72)` | window frame, and the crosses at its corners |
| `--ink` / `--ink-muted` / `--ink-dim` | `#eef0f1` / `#b7bcc1` / `#9aa1a8` | 16.8 / 10.0 / 7.3 : 1 on ground |
| `--cortex-accent` | `#c3b6dd` | Cortex's identity. OKLCH L 0.800, C 0.055, hue 300 (Shield's `#9fc3df` is hue 242) |
| `--status-anchored` / `-review` / `-conflict` | `#9fc3df` / `#d7aa6c` / `#d88383` | the shared vocabulary; identical in Shield |
| fonts | **Raleway** for everything but code: 600 for headings and metrics, 400/500 for prose and every control; JetBrains Mono for anything hashed or addressed | load Raleway 400/500/600/700 (variable) and Mono 400/500. Raleway's default figures are old-style, so `font-feature-settings: 'lnum'` is set on every element (`console.css`). There is no condensed Raleway, so headings are set smaller than the condensed face allowed, and the rail wordmark stacks on two lines |
| geometry | window padding/gap 20, control height 38, tab 40, content max 1440, gutter 42 | |

Rules that are easy to break:

- **Everything is square** (`radius: 0`). **Flat**: the only shadow is `--shadow-overlay`, for drawers.
- **Windows** get a `frame-line` rule and a cross at each corner (`.xc-win`). Marks never nest; a clipping
  ancestor needs 6px of padding or the crosses shear.
- **Controls are not windows**: they keep `hairline`. Sentence case on buttons, tabs, nav; UPPER CASE only
  for eyebrows, table heads and small tags.
- **A tag is transparent** (colour in the label and a stroke icon); a **callout** (a whole-row statement
  of state) keeps its `*-soft` fill. Colour is never the only signal: every status has a word.
- **Say what a control does to the system**, next to the control, before the person commits. Counts say
  whether they are exact. No exclamation marks, no emoji. An error names what failed and what to do.
- Icons: inline stroke SVG, 24 viewBox, `currentColor`, 1.8 stroke; an icon-only button has `aria-label`.
- Never use Shield's accent inside Cortex or the reverse.

## 4. Information architecture

| Destination | Surface | Opens from |
|---|---|---|
| **Graph**, **Timeline** | the workspace | the rail (or top bar, or phone tab bar) |
| Memories, Entities, Sessions | drawer, wide | the counts in the Filters pane; "Neighbours and paths" on an entity; "Exchanges, replay, telemetry" on a session |
| Operations | drawer | the connection chip at the foot of the rail |
| Agents | drawer | "Agents and devices" under the scope picker |
| Settings | drawer | the Tools strip |
| Recall, Review, Integrity | dialog / drawer | `⌘K`; the Tools strip; the workspace summary |

- **Route grammar** (`nav.ts`): `` (graph), `#timeline`, `#settings` (a drawer over the graph),
  `#timeline/sessions` (a drawer over the timeline). Closing a drawer returns to the lens under it.
- **Three shells, one registry** (`nav.ts` is the only list): left rail (default), top bar, and a phone tab
  bar (Graph, Timeline, Recall, Review, More). A drawer is a full-screen sheet on a phone.
- **Collapsible**: the rail and the top bar's second row collapse to icons (`railCollapsed`); the Filters
  and Inspector panes hide from the ends of the lens bar (`facetsCollapsed`, `inspectorCollapsed`). All
  persist in `localStorage` (`xibalba-cortex.console-settings`, parsed field by field in `settings.ts`).
- With nothing selected the Inspector shows the **workspace summary**, so the pane is never dead space.

## 5. The graph lens (the part with the most rules)

Behaviour is specified in `DESIGN.md` ("Graph lens: the spec"). The numbers, so you do not have to find
them:

| Rule | Value / where |
|---|---|
| default view | 3D; 2D toggle; persisted (`graphMode`). No WebGL → 2D and a notice |
| nodes | cubes (3D), squares (2D); one per lattice cell, cell = 24 units; priority by degree, then id; hysteresis 0.62 (`gridSnap.ts`) |
| snap to grid | `graphSnap`, default on; a bar button and a Settings checkbox. Off: nodes stay where the force layout leaves them |
| grid | faint in both. 3D: a lattice through the volume + a brighter box; 2D: a square grid. Both coarsen by powers of two to stay ≥ 14px (3D) / 16px (2D) apart (`latticeStride`) |
| framing | camera looks along the cloud's thinnest axis (PCA, Jacobi) with a tilt, at the nearest distance that holds every cube in the real frustum (`framing.ts`). Re-frames on filters until the person moves the camera; Fit re-arms it |
| resolution | cube ≥ 5px (3D), square ≥ 3.5px (2D); arrowheads ≥ 10px; selected-edge bar ≥ 2px; overlapping labels dropped (selected and hovered first); near stop 16 units, far stop 2.5× the framing distance; zoom toward the pointer |
| selecting | click a node or a line (6px); a selected edge lights its two ends and dims the rest |
| dragging (3D) | drag a cube on the plane facing the camera → it lands in the nearest free cell and is **pinned** (outlined); double-click unpins; "Unpin n" unpins all. Pins are view state, nothing is written |
| keyboard (3D) | focus the canvas: arrows orbit, shift+arrows pan, `+`/`−` zoom, `F` or `0` frame all, `Esc` clear. No keyboard way to pick one node (use the Inspector or Recall) |
| edges | relation (accent, arrow subject→object), contradiction (dashed, review), similarity (dotted, anchored), structure (grey: contains, prompt, response, context, Merkle root). Each group, structure type and relation predicate has a switch; the legend rows are the same switches |
| hidden selection | if a filter hides the selected item the lens says so and offers "Reset facets"; the Inspector still shows it |

Pure logic, fully tested: `model.ts`, `gridSnap.ts`, `framing.ts`, `graphStyle.ts`, `settings.ts`, `nav.ts`.
**Not** unit-tested: `Graph3D.tsx` (a WebGL engine) and the 2D canvas painting; they were verified by hand.

## 6. Architecture map

| File | Responsibility |
|---|---|
| `ConsoleApp.tsx` | sign-in gate; the workspace (`[facets │ lens │ inspector]` + chain rail + status bar); mounts the page drawer and the three dialogs |
| `state.tsx` | `ConsoleProvider`: scope, loaded data, selection, facets, time window, route, `openPage(page, arg)` |
| `nav.ts` | the destination registry, route parse/serialise (**one list for all three shells**) |
| `PageDrawer.tsx`, `pages/*` | the drawer frame; the six page bodies. `Page.tsx` drops its own title inside a drawer |
| `Shell.tsx`, `Phone.tsx` | rail, top bar, status bar; phone tab bar and sheets |
| `GraphLens.tsx`, `Graph3D.tsx`, `TimelineLens.tsx` | the two lenses; `Graph3D` is the three.js engine |
| `FacetRail.tsx`, `Inspector.tsx`, `ChainRail.tsx`, `PaneToggle.tsx` | the panes around the lens |
| `Recall.tsx`, `Review.tsx`, `Integrity.tsx`, `VerifyPanel.tsx`, `MemoryActions.tsx` | the dialogs/drawers and the write actions |
| `ConfirmPanel.tsx`, `workspaceActions.ts` | the confirm-before-acting panel, and the pure wording and arithmetic for export, import, attach, link verification, anchoring, backup, ending a session |
| `status.ts`, `runtime.ts`, `access.ts`, `passwordReset.ts` | pure wording for workers/runtimes/vault, policy interventions on the Timeline, tokens and the profile view, password reset |
| `pages/OpsStatus.tsx`, `pages/settings/AccessSection.tsx`, `ProfileSection.tsx` | Operations cards (runtimes, workers, connectors, backup); Settings → Access and Profile |
| `model.ts` | payload → graph model; facets; time placement (event time → exchange time → `created_at`) |
| `data.ts`, `workspace.ts`, `../api.ts` | loading; scope (agent/store/primary); every HTTP call and the CSRF handling |
| `settings*.ts(x)`, `tokens.css`, `console.css`, `palette.ts` | browser preferences; the theme |

Scoping is **fail-closed**: a write needs a *verified, writable* `{store, agent}` namespace
(`workspace.canWrite`); "Primary profile" is an explicit, always read-only choice and is never selected
automatically. Cookie sessions send a CSRF token on writes; a bearer token does not need one.

## 7. Honesty rules (the project's reason for existing)

1. **No silent mocks.** If something is not built it is `[PLANNED]` with a visible banner; never code that
   pretends. The predecessor of this project faked ZK proving, TEE attestation and OPA.
2. **"Server reports" is not "verified in this browser".** Merkle validity is labelled server-reported;
   inclusion proofs and session proofs are recomputed in the browser and labelled so.
3. **`on_chain: false` is not "off-chain".** When the oracle is unreachable the tag says *Status
   unverified* / *Not checked*.
4. **No path ever comes from the browser.** Backup destination, vault directory, DAG location and the
   anchor service are server configuration; the browser sends an id or a hash.
5. **Outward actions are confirmed and named** (anchor, rebuild). **Results are worded as what they are**
   (a backup check shows the copy is complete, not that it restores; a link check is byte lineage only).
6. **Extraction is proposal-only.** Nothing reaches the graph without a decision in Review.
7. Timestamps: a node is placed in time only from a time the API really returns; the rest are *untimed*
   and never hidden by the time window.

## 8. Where each formerly planned capability lives (all built)

| Capability | Surface | Backend |
|---|---|---|
| Forgot password; choose a new password | Sign-in (`SignIn.tsx`, `passwordReset.ts`) | `POST /api/auth/password-reset/{request,confirm}`; the emailed link carries `?token=`, removed from the address bar on load |
| Accounts waiting for approval | Settings → Access | `GET /api/auth/admin/pending` (admin), `POST /api/auth/admin/approve` |
| API tokens | Settings → Access | `GET/POST /api/auth/tokens`, `POST /api/auth/tokens/revoke` (`console_admin.py`) |
| Profile (read-only) | Settings → Profile | `GET /api/profile/config`: no path, no secret |
| Trust vault lookup | Settings → Developer | `GET /api/vault/leaf` (`XIBALBA_VAULT_DIR`) |
| Agent runtimes | Operations | `GET /api/runtimes` (`console_status.py`) |
| Runtime on the Timeline | Timeline lane marks + session Inspector | from `GET /api/invocations`: a denied or asked tool call is a tall bar on its lane (`runtime.ts`) |
| Workers | Operations | `GET /api/workers`: derived from the queue, **no heartbeat** (the v1 schema is frozen) |
| Connectors and ingest | Operations | `GET /api/connectors`: reports ingest, never drives it |
| Backup and check | Operations | `GET /api/backups`, `POST /api/backup`, `POST /api/backup/reconcile` (`XIBALBA_BACKUP_DIR`; the server names the file) |
| Attach a file | Inspector → Files | `POST /api/memory/{id}/attachments`: raw bytes, streamed, up to 200 MB |
| Import a document | Memories | `POST /api/import`: text and Markdown, candidate memories plus review proposals |
| Export this window | Chain rail | `POST /api/provenance/export`: the ids the window and Filters show, each scope-checked |
| End a session | Sessions | `POST /api/session/{id}/end`: not undone, confirmed first |
| Verify an integrity link | Integrity → Links | `POST /api/memory/{id}/verify-link` (`XIBALBA_DAG_HOME`): byte lineage only |
| Anchor a session root | Integrity → Sessions | `POST /api/session/{id}/anchor` (`XIBALBA_ANCHOR_URL`): outward, confirmed, store operator |

Every outward or irreversible action uses `ConfirmPanel.tsx` (what it will do, then a named button, Escape
backs out) and words its result in `workspaceActions.ts` / `status.ts` / `access.ts` (pure, unit-tested).

**Machine protocols stay machine protocols.** There is, and should be, no UI for: the 27 `runtime_*` harness
hooks, the worker `claim`/`complete` protocol, connector ingest, `memory_embed`, `memory_ingest_agent_turn`,
`memory_session_start`, OTLP batch ingest. The console reports on them (runtimes, workers, connectors); it must
not let a person impersonate a worker.

## 9. Known gaps and caveats (so nothing surprises you)

- **Stubbed responses in tests**, only where the fixture cannot produce the case, each named as such in the test:
  a working mail server and a valid emailed secret (password reset success), an administrator credential
  (approving accounts), a trust vault (the five vault outcomes), and the signed-in Account data (the dev proxy
  is a token, not an account). Everything else runs against the real API.
- **No worker heartbeat.** Worker state is inferred from the queue, so an idle worker and one that is down look
  alike when nothing is waiting. A heartbeat needs a schema migration and a spec amendment; the console's
  wording already keeps "idle", "backlog" and "no work seen" apart.
- **Store-wide scoping** was recorded earlier on some read routes (review proposals, PARA, memory-by-id,
  integrity-links, projection routes can reach memories outside the selected agent). The console filters what
  it shows and the new store-wide routes require an unbound operator, but the older routes should enforce scope
  on the server. **Re-verify before relying on it.**
- **Password reset**: for an address with an account and no mail delivery configured the server answers `503`,
  for an unknown address `200`, which tells a probe the account exists. It only happens on a server where reset
  cannot work at all; fixing it means answering `200` there too, which would tell the person a link is coming
  when none is. A deployment decision, not a UI one.
- **Graph panels in the mockups are images** of the 3D canvas; the live console is interactive. The 3D canvas has
  no keyboard way to pick a single node (use the Inspector or Recall).
- **Mockups need a recapture** after the Raleway, ground-colour and surface changes (`design-tools/README.md`);
  the design-system artifact's own text still describes Barlow and the old ground, and Shield keeps Barlow.

## 10. Suggested next steps

1. **Recapture and republish the mockups** (`design-tools/`): every board changed with Raleway, the `#0d0f11`
   ground and the new surfaces; the planned boards become captured ones.
2. **Server-side scoping** for the older store-wide read routes (section 9), with a test per route that an
   agent-bound credential cannot reach another agent's data.
3. **A worker heartbeat**, if "is it running?" matters more than "is it keeping up?": a table, a spec amendment,
   and one call per worker loop. Then `console_status.worker_status` can say `down` truthfully.
4. **Update the design system** (Raleway; `#0d0f11`; the confirm panel, verdict callout and intervention marks).
5. Keep the gates green: `tsc -b`, `oxlint`, `vitest`, `npm run test:e2e`, `uv run pytest -q`.

## 11. Conventions for the code you write

- Match the file you are in. The console is **densely commented with the reason**, not the what; keep it
  that way, and put a doc link where a standard is the reason
  (e.g. [Jacobi eigenvalue method](https://en.wikipedia.org/wiki/Jacobi_eigenvalue_algorithm),
  [PCA](https://en.wikipedia.org/wiki/Principal_component_analysis)).
- Put logic that can be pure in a pure module with a test (`framing.ts`, `gridSnap.ts`); keep components thin.
- State the failure posture (fail open / closed) for any new failure path, in the module's own docstring.
- Do not add a destination: add a drawer entry point in context. If a thing is needed from both lenses it
  belongs in the Inspector, the Filters pane or the chain rail.
- Never push to `main`; open a draft PR; CI must be green. Update `COVERAGE.md`/`DESIGN.md` in the same change.
